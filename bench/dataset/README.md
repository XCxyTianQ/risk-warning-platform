# T5 数据集管线（风险预警层的"真值"从哪来）

> 一句话：**不靠人力翻公告**。风险事件在权威信源上本来就带日期、带原文，
> 我们把它们自动采下来，做成"企业 × 时点 × 标签"的样本，再做 point-in-time 评测。

## 一、数据从哪来（全部为公开信源，可回溯）

| 用途 | 信源 | 接口 | 实测 |
|---|---|---|---|
| 全 A 股清单 | 东方财富行情快照 | `push2.eastmoney.com/api/qt/clist/get` | 5,558 只（含 320 只 ST/*ST） |
| **事件标签** | **巨潮资讯**（交易所指定披露平台） | `cninfo.com.cn/new/hisAnnouncement/query` 全文检索 | 行政处罚 2,941 条、退市风险警示 6,108 条… |
| 财报面板 | 东方财富 datacenter | `RPT_DMSK_FN_BALANCE` / `RPT_LICO_FN_CPD` | 按代码取全部报告期，含**披露日期** |

每条事件都带：`类型 / 严重度 / 命中关键词 / 披露日期 / 公告标题 / PDF 链接`——**任何人可以点开核对**。

## 二、标签口径（`labels.js`，可审计）

9 类事件：行政处罚、立案调查、退市风险警示、其他风险警示、债务违约、资金占用/违规担保、
财务造假/会计差错、被执行/失信、非标审计意见。每类都有**关键词 + 排除词**（避免把"未被处罚"的澄清公告算成处罚）。

> 改词表 = 改标签口径 → 必须重新采集并在 `manifest.json` 留痕（含文件 sha256）。

## 三、用法

```bash
# 采集（首次约 5–10 分钟；公开接口有限流，脚本已做 IPv4 优先 + 退避重试 + 空结果保护）
node bench/dataset/fetch.js --cases 120 --controls 120 --since 2018-01-01

# 只更新标签（快），或只补面板
node bench/dataset/fetch.js --events-only --keywords "退市风险警示,行政处罚决定书,立案调查"
node bench/dataset/fetch.js --panel-only --codes 002069,600518

# T5 评测（point-in-time + 时间切分）
node bench/dataset/t5.js --target risk_warning_next_year
node bench/dataset/t5.js --target penalty_next_year
```

产出（`bench/dataset/out/`，**不入库**，可随时重抓）：

```
universe.jsonl   全 A 股清单（代码/名称/行业/上市日/是否 ST）
events.jsonl     事件标签（含证据链接）
panel.jsonl      财报面板（含 reportDate 与 noticeDate）
cohort.json      本次队列（病例=现 ST；对照=随机）
manifest.json    参数 / 来源 / 每条关键词抓取量 / 窗口命中总数 / 文件 sha256
t5-report.json   T5 指标与样例（**这份入库**，便于对照与答辩）
```

## 四、评测口径（不这样做，指标就是假的）

1. **point-in-time**：特征只用 `noticeDate ≤ T` 的财报（披露日期，不是报告期）；
   标签只用 `T < event.date ≤ T+12个月` 的事件。**严禁未来信息进入特征**。
2. **按时间切分**：训练 ≤2023-12-31，测试 ≥2024-01-01（不是随机切分）。
3. **病例-对照 + 基础率**：队列里 ST 被过采样，报告同时给原始正例率与测试集基础率。
4. **预测器可插拔**：v0.1 内置"财务困境规则分"基线（透明、可复算）；
   平台自身评分通过 replay 接入（下一步），两者用同一套指标对比。

指标：`ROC-AUC`、`PR-AUC(AP)`、`Top-K 精确率/召回`、**提前预警期中位数（天）**。

## 五、第一次实测（2026-09-13，120 病例 + 120 对照）

| 项 | 值 |
|---|---|
| 采集 | 4,000 只清单 / **8,894 条事件** / 11,600 条报告期 |
| 样本 | 1,460 个（企业 × 时点），正例 40（2.7%） |
| 切分 | 训练 1,270 / 测试 190（正例率 6.3%，全部为退市风险警示） |
| **基线 ROC-AUC** | **0.526** |
| **基线 PR-AUC** | **0.078**（随机 ≈ 0.063） |
| Top-19 精确率 | 10.5%（随机 6.3%） |
| 提前预警期中位数 | 266 天 |

**怎么读这个结果**（诚实版）：

- 一个 1990 年代风格的"高负债 + 亏损 + 负权益"规则，**几乎打不过随机**——
  说明"提前 12 个月预判退市风险"本身就是硬任务；
- 这给了平台一个**必须超过的下限**：如果我们的六维评分在这个测试集上做不到明显高于 0.526，
  那"AI 预警"就没有证据说自己比财务规则强；
- 也暴露了数据集本身要改的地方（见下）。

## 六、下一步（把 T5 做成真正能说话的东西）

| 项 | 做法 | 预期 |
|---|---|---|
| 扩队列 | 不只"现 ST"，改成**历史上曾被实施退市风险警示/处罚过的全部企业**作为病例；对照扩到 500+ | 正例从 40 → 数千 |
| 拉长时间 | `--since 2015`，面板已有全部报告期 | 覆盖更多完整事件周期 |
| 多目标 | 主目标加 `penalty_next_year`（处罚/立案正例多得多） | 指标更稳（置信区间更窄） |
| **平台评分 replay** | 按 cutoff 重建"当时可见"的库状态 → 问平台要评分 → 与基线同台比 | 回答"我们到底比规则强多少" |
| 交叉验证标签 | 巨潮 + 东财 + 交易所公告三源比对，不一致进人工复核队列 | 标签可信度分级（A/B/C） |
| 更激进（可选） | 加入债券违约（银行间/交易所）与"失信被执行"企业；把非上市企业纳入 | 跳出"只有上市公司"的样本偏差 |

> 边界：本管线只做**公开数据**，不做任何内幕/非公开信息；标签是"事后事实"，
> 用途是评测预警能力，不构成投资建议。
