06短板与反例：这一轮测出来的真问题

一份只报喜的报告没有价值。以下四条都是我们自己测出来打自己脸的结果，附改进方向。

6.1 平台链路在客观题上比直连模型低 18.8 个百分点

图 4　同一批题：口径 A（直连模型）vs 口径 B（经平台 /api/chat/stream，含平台系统提示词与 25 个工具）
读法与动作 纯客观题上，平台链路与直连模型唯一差别就是"平台系统提示词 + 工具清单"。因此这 18.8 个百分点不应归因于模型能力， 而是平台在"客观问答"场景下的提示词/编排开销：模型的注意力被人设与工具说明占据，逐题明细里能看到答非所选与空回答。 改进方向：按场景裁剪系统提示词与工具集（客观问答不需要 25 个工具）。 反过来说，平台自己实现的附件读取链路在图片题上与直连持平（18/20），这条结论比图片题分数本身更值钱。

6.3 其余三条如实记录

  • 退市目标的 AP 仍低于基线（18.0 vs 19.5）：AUC 全面领先，但排序质量在正例极少的场景下仍不稳。
  • 工具"应拒调"只有 74.17%（31/120 次不该调用却调用了），这是平台工具层需要加护栏的地方。
  • 复现性：同一配置把 FinanceBench 跑两遍，裁判口径 oracle 83.33% → 82.00%、closedBook 47.33% → 44.67%， 因此本页数字只用于判断量级与方向，不用于比较小数点后差异。

09局限与未做：这一页没有覆盖到什么

尚未纳入的评测层

  • T2 图片/扫描件读取（≥150 张）与 T6 Agent 工具链（≥120 条意图）尚未纳入自建基准——本轮只用外部 FinEval-MM / BFCL 间接覆盖。
  • T7 报告生成质量（数字可核验率、幻觉率、双人评分 κ）未做。
  • 长稳测试（8 小时 / 2000 请求）与数据量放大后的性能未做：当前时延是在小库上测得。

口径与样本上的取舍

  • 单模型：全部结果由 deepseek-flash 产生，没有跨模型对比；验收项已改为"口径 A vs 口径 B"。
  • 外部基准只做抽样：不宣称跑过全量；FinEval 经典学术题未公开、FinanceBench 只开源 150 题、BFCL 榜单未归档分数。
  • 合成样本的边界：T1/T3 用的是"真实形状的合成财报"，接入真实数据后必须重跑。
  • 因果性弱：ST / 处罚是事后标签，只能说明"更早识别出信号"，不能说明"避免了风险"。
