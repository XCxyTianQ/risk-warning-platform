# v1.0.0（2026-09-15）正式版

## 一句话

把「条件化 A1」落回产品的尝试**失败并被证伪**，真正起作用的是**生态四层的连接**——因此本版按生态形态重构：
**提示分节 + 内置技能 + 内置预设（挂载）+ 工具默认可用**，并用三个基准的实测数据划清了它的边界。

## 一、本版做了什么

| 层 | 变更 |
|---|---|
| **Prompt** | `backend/src/agent/prompt.rs` 新增「**作答模式**」路由分节：先判问题类型再决定是否调工具（通用知识直接答、企业数据必走工具、固定方法论走技能）；并新增「证据与推导纪律」 |
| **Prompt** | **撤掉**"证据充分性与作答规则"整段——实验证明其惰性（净 0 题，z=0.00） |
| **Skill** | `backend/src/services/skills.rs` 新增内置技能「**金融客观题作答**」（题型识别 / 禁调工具 / 严格输出契约 / 不留空） |
| **Preset** | `backend/src/services/presets.rs` 新增内置预设「**客观题 / 知识问答模式**」，`skills=["金融客观题作答"]`（**把提示与技能接起来的那一环**） |
| **Tools** | **保持默认全可用**；不做全局关闭（B1 实验证明单独去工具会更慢且拒答更多） |
| **版本** | `backend/Cargo.toml` 与 `desktop/package.json`：0.7.2 → **1.0.0** |

## 二、实测效果（口径 B：平台链路；FinanceBench oracle 150 题）

| 指标 | 改动前 | v1.0.0 + 内置预设 | 变化 |
|---|---|---|---|
| 准确率 | 86.58% | **88.85%**（2 轮） | **+2.75pp**（相对"无预设默认"，配对 z=2.11，**显著**） |
| 拒答率 | 2.68% | **1.01%** | 显著下降 |
| 耗时/题 | 5,009 ms | **3,185 ms** | **−36%** |

## 三、效果边界（本版最重要的发现）

同一条"挂载预设"处理，**在不同任务类型上方向相反**：

| 基准 | 任务类型 | 效果 |
|---|---|---|
| FinanceBench | 从给定材料取数作答 | **+2.75pp**（显著） |
| CFLUE | 通用金融知识客观题 | **−2.67pp** |
| FinEval-MM | 财报图表截图四选一 | **−2.01pp** |

**结论**：该预设**不是通用能力提升，只是"证据问答模式"的增益**。
因此本版**将其保持为可选预设，不设为默认**——设为默认会在客观题与图表题上各退化约 2~3 题。

## 六、诚实标注的局限

1. **准确率提升未在"改动前基线"上达显著**（该配对 z=1.71，p≈0.087；改动前仅 1 次运行）——
   可声称的是"相对无预设默认显著提升"，不是"相对旧版显著提升"。
2. n≈150/次、判分多为 deepseek-flash 自判 judge@1（单次噪声 ±2~3 题）；
   客观题基准（CFLUE / FinEval-MM）用确定性判分，无裁判噪声。
3. FinEval-MM 两组的 −2.0pp ≈ 3 题，方向与 CFLUE 一致但未做配对显著性检验。
4. 本轮曾在 `uploadImage` 缺超时的缺陷下把 40 分钟长任务误判为"挂死"，已修复并更正记录。

## 七、致谢与教训

**能力不是一句提示词能解决的，而是"工具 + 提示 + 技能 + 模型"的生态**——本版用实验证明了这一点：
- 只加提示与技能库（不挂载）→ **净 0 题**（z=0.00）
- 仅去工具 → 更慢、拒答更多
- **把技能挂上（预设挂载）→ +2.75pp 显著**

同时证明了**生态各层必须对准任务的缺口**：同一条规则在证据问答上是增益，在知识题与图表题上是轻微退化。
