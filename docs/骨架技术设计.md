## 1. 概述

本平台面向企业经营风险预警场景：以多模态大模型为核心，融合财务、法律、舆情等多源数据，
提供**分级预警、证据追溯、根因分析**能力。本设计文档介绍工程骨架（阶段1）的技术设计，
并明确阶段2~6 在骨架上如何生长。

**技术栈决策（负责人确认后不再变更）：**

| 层 | 选型 | 版本/说明 |
|---|---|---|
| 后端 | Python + FastAPI + uvicorn | Python 3.14.3 / FastAPI 0.141.1 |
| HTTP 客户端 | httpx | 大模型 API 调用、外部数据源 |
| 配置 | pydantic-settings | 环境变量 + `.env` |
| 数据库 | SQLite（原型）→ PostgreSQL（正式） | DATABASE_URL 切换，表结构先留接口 |
| 前端 | Vue 3 + TypeScript + Vite | Vue 3.5 / Vite 8 / vue-tsc 严格校验 |
| 图表 | ECharts（阶段2 引入） | 雷达图、时间线、大屏 |
| 大模型 | OpenAI 兼容接口 | 默认 `deepseek-v4-flash-vision-exp`（多模态）；备选 `deepseek-v4-pro` / `deepseek-v4-flash`；离线用本地 mock |
| 部署 | Docker + 云服务器（阶段6 后置） | 先生本机跑通 |

**端口约定（本机 8000 被无关服务 `node server.js` 占用，故统一切换）：**

| 服务 | 端口 | 说明 |
|---|---|---|
| FastAPI 后端 | **8001** | `127.0.0.1:8001` |
| mock 大模型 | 9000 | `127.0.0.1:9000/v1`（OpenAI 兼容） |
| Vite dev | 5173 | `localhost:5173`（绑定 `::1`，勿用 127.0.0.1） |

### 4.3 大模型接入层 `server/app/llm/` ★

骨架期接口先行、实现后置（client.chat / agent.turn 标注 TODO 与实现依据）。

#### 4.3.1 `client.py` —— OpenAI 兼容网关

```python
class LlmException(RuntimeError):
    status_code: int          # -1=网络/IO/中断；0=响应异常；其它=HTTP状态码
    def retryable(self) -> bool:
        # 网络错误 / 408 / 429 / >=500 可重试；4xx（schema/鉴权）不可重试
        return self.status_code < 0 or self.status_code in (408, 429) or self.status_code >= 500

@dataclass(frozen=True)
class LlmConfig:
    base_url: str; api_key: str; model: str
    max_tokens: int = 1024; timeout_s: float = 90.0; max_retries: int = 2

class LlmClient:
    def __init__(self, config: LlmConfig): ...      # httpx.Client 常驻连接
    last_prompt_tokens: int                        # usage.prompt_tokens（上下文压缩触发用）
    def chat(messages, tools=None, max_tokens=None) -> dict     # TODO(阶段2)
```

**阶段2 实现要点（照搬 reasonmc 并经差分调整，详见调研文档）：**

1. 三参数由 `Settings` 构造 `LlmConfig` 注入；
2. **先检查 HTTP 状态码再解析 body**（非 2xx 可能是 HTML/空，给可读错误）；
3. 解析防御链：body null → `error` 字段 → `choices` 空 → 取 `message`；
4. 记录 `usage.prompt_tokens`；
5. 统一抛 `LlmException`，供 agent 层 `retryable()` 退避重试。

#### 4.3.2 `tools.py` —— 工具注册表

```python
class ToolRegistry:
    def register(name, schema, handler) -> None          # 重复注册抛 ValueError
    def definitions() -> list[dict]                      # OpenAI function 格式 schema
    def tools_for_request() -> list[dict]                # 随 body 发送
    def call(name, args) -> str                          # 分发执行；未知/异常 → "ERROR: ..."
```

- 工具执行**以文本回注**给 LLM（`ERROR: ...` 不中断循环），由模型决定下一步（reasonmc 同款策略）；
- **白名单**：仅注册过的工具可被调用（防 prompt 注入调用敏感工具，阶段2 落实）；
- 首批工具（阶段2）：`get_finance_data` / `get_legal_records` / `get_news` / `get_rules`。

#### 4.3.3 `agent.py` —— 风险研判 Agent

```python
class RiskAgent:
    def __init__(self, llm, tools, memory=None): ...
    def turn(self, prompt: str) -> str: ...              # TODO(阶段4)
```

**阶段4 实现要点（照搬 reasonmc AgentLoop）：**

- 单轮流程：`user → LLM(带 tools) → tool_calls → 逐个执行回注 → 再调用 → 直至纯文本回复`；
- `max_turns`（8）上限防死循环；超界返回提示；
- `chat_with_retry`：指数退避 500ms→1s，仅重试 `retryable()`；
- 上下文恒定：`system_prompt + [企业事实记忆块] + 最近 N 轮`，体积不膨胀；
- 每轮结束 MemoryExtractor 增量提取事实 → MemoryStore 合并落盘；
- system prompt 支持热更新（阶段4 从配置/DB 读取）。

#### 4.3.4 `memory.py`（阶段2 建立）

- `MemoryStore`：事实列表 `{text, ts}`；去重刷新 ts；上限 200 条/单条 200 字，超限裁最旧；
  **原子写盘**（tmp + ATOMIC_MOVE，降级 REPLACE_EXISTING）；加载失败 fail-open 不阻塞；
- `MemoryExtractor`：LLM 增量提取"新增事实/旧事实更新"，`<memories>` 标签解析，无新事实输出空标签；
- 本项目语义：事实 = 企业风险信号（如"2026Q1 资产负债率 78%，同比 +12pp"），
  渲染注入上下文供研判，同时落库 `risk_fact` 表供**证据引用与人工复核**。

### 4.5 六维评分模型（企业评分画像）

前端「企业评分画像」的数据来源（`app/services/rules.py`）。每个维度 0~100 分（**越高越健康**），
数据不足的维度返回 `None` 并标记 gray，不参与综合评分。

**数据状态门控（关键原则：没有数据 ≠ 没有风险）**：企业表 `data_status_json` 记录每个维度的采集状态——

| 状态 | 含义 | 评分行为 |
|---|---|---|
| `ok` | 已采集且查到记录 | 按规则打分 |
| `empty` | 已采集但确实没有（如无诉讼、无负面新闻） | 可判 0 风险（100 分） |
| `never` | 从未采集（如非上市无财报） | **gray，不参与评分** |
| `error` | 采集失败 | **gray，不参与评分** |

若某企业所有维度都是 `never/error` → 综合评分为 `None`、评级显示「无数据，无法评估」，
避免出现"无数据却 100 分"的假画像。添加企业时若三源皆无记录，直接撤销建档并报错。

| 维度 | 中文名 | 主要信号 | 扣分规则（摘要） |
|---|---|---|---|
| finance | 财务健康 | 资产负债率、净利润、连续亏损 | ≥85% −45；≥70% −30；≥60% −15；净利润为负 −25；连续两年亏损 −10 |
| legal | 法律合规 | 涉诉数量、涉案金额、行政处罚、刑事 | 每条 −6（上限 −50）；行政处罚 −10；刑事 −20；涉案≥1亿 −10 |
| news | 舆情声誉 | 负面舆情占比、近一年负面 | 负面占比×120（上限 −60）；近一年负面每条 −3（上限 −15） |
| operation | 经营能力 | 成立年限、净利润率、营收增速 | 成立<2年 −10、<5年 −5、≥10年 +5；净利润率为负 −30；营收下滑 −15 |
| credit | 信用状况 | 失信、被执行、行政处罚 | 失信 −40/次（上限 −45）；被执行 −30/次（上限 −35）；行政处罚 −12/次 |
| supply | 供应链稳定 | 合同类纠纷、供应链负面舆情 | 纠纷 −8/项（上限 −45）；供应链负面舆情 −8/条（上限 −25） |

综合评分 = 可用维度平均分 → 评级：**AAA**≥90 优秀 · **AA** 80~89 良好 · **A** 70~79 稳健 ·
**BBB** 60~69 关注 · **BB** 50~59 预警 · **C** <50 高风险。
风险等级映射：≥85 正常 · 70~84 关注 · 55~69 较高风险 · <55 高风险。

实测样例（规则引擎，不调用大模型）：

| 企业 | 综合评分 | 评级 | 财务 | 法律 | 舆情 | 经营 | 信用 | 供应链 |
|---|---|---|---|---|---|---|---|---|
| 贵州茅台 | 100 | AAA | 100 | 100 | 100 | 100 | 100 | 100 |
| 杭州深度求索 | 90.0 | AAA | — | 80 | 80 | 90 | 100 | 100 |
| 宁德时代 | 85.3 | AA | 85 | 88 | 55 | 100 | 100 | 84 |
| 獐子岛 | 48.7 | C | 20 | 50 | 25 | 55 | 58 | 84 |
| 康美药业 | 33.2 | C | 20 | 10 | 25 | 55 | 13 | 76 |

> 阈值集中在 `rules.py` 的 `dim_score()`，阶段3 拿到真实数据后按评测集调参。
