01核心发现：闭卷之后，排名变了意思

把文档完全拿走之后，
排名第一的模型仍然答对 86.67%。

FinanceBench 的 oracle 口径是把标注好的证据段落直接喂给模型，常被当作"读财报能力"。 我们补了一个对照实验：完全不给文档，只给问题。于是每个模型都得到两个分数——

  • oracle：给了文档能答对多少
  • 闭卷：不给文档还能答对多少（≈ 记忆底分）
  • 文档增量：两者之差，才是"读文档"真正带来的能力

最贵档的 Fable 5.1 闭卷就能答对 86.67%， 文档只为它带来 +8.00pp； 而文档为我们带来 +40.67pp， 是它的 5.1 倍。 抽查还看到它自己在答案里写 "Based on FY2022 figures from memory"，并复现出只有读过原文才知道的数字。

07边界：这份展示没有覆盖到什么

口径

闭卷不等于纯记忆：部分题可凭通用金融常识推导，且闭卷提示词鼓励推导，因此闭卷分是污染的上界估计。

判分

BFCL 判分是官方 checker 的自实现移植，OmniDocBench 四项是自实现保真度指标（非官方 TEDS/CDM），不得与官方榜单直接等同。

样本

FinanceBench 用的是开源子集 150 题；闭卷对照只在这一组题上做过，"记忆红利"的结论仍需换一个未被污染的基准复验。

未做

T6 Agent 工具链未纳入自建基准；长稳测试（8 小时 / 2000 请求）与放大数据量后的性能未做。

成本

Luna 与 GLM-5.3-Flash 的网关价目未公布，只记 token 不估钱；我们的成本按官方 peak 价计，实际可能更低。

产品链路

平台后端附件目前只接受图片、不支持 PDF；PDF 抽取与检索在评测侧完成，产品化需要补后端 PDF 能力。
