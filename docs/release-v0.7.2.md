## 一、修复：旧数据目录上的写路径（P0）

**现象**：升级后新建对话报 `NOT NULL constraint failed: chat_session.summary`；
新增企业、生成预警同理失败。老数据能看、能查，就是写不进去。

**根因**：旧库是 Python/SQLAlchemy 建的，大量列是 `NOT NULL` 但**没有 DEFAULT**；
而 Rust 侧的 INSERT 只写自己关心的列、其余依赖默认值补齐。新装用户（库由 Rust 建，列都有默认值）
不会遇到，所以此前所有测试都没发现。

**修复方式**：启动时做一次通用"旧表重建"迁移——凡"旧列 NOT NULL 无默认值、而新结构给了默认值"的表，
在**一个事务内** `改名 → 按新结构建表 → 拷贝列交集 → 删除旧表`，随后补建索引。

**已验证**：

- 新增自动化套件 `legacy-db-compat`（配一份随仓库提交的旧 schema 夹具）：
  修复前在 v0.7.1 上**复现失败**，修复后 13 项断言全过；
- **拿真实数据目录的副本做迁移预演**：13 张表重建，企业 5 / 财报 8 / 新闻 58 / 司法 21 / 技能 5 /
  预设 4 / 设置 13 行**全部零丢失**，新建会话与新建表格均返回 200，日志无错误。

> 升级只需覆盖安装，首次启动会自动迁移（几秒），数据目录位置不变。

## 三、同时修掉的三处"假通过"

1. `smoke-media` 原来只看弹窗是否出现、选择器还写错了 → 现在断言到"识别字段数、写入格子数、
   确认后待确认标记归零、入库按钮可用"；
2. `probe-compaction` 默认 128k 窗口下 4 轮根本压不到阈值，跑完也不报错 → 改为单独起小窗口后端，
   并用 `compact_count ≥ 1` 作为硬断言；
3. `probe-p4` 的"工具集合完全相等"在参考实现冻结（v0.4.4）后必然失败 → 改为
   "参考实现的工具必须全部仍在"（Rust 侧新增表格/多模态工具属预期）。

## 六、已知边界

- 公式仍在前端计算；不支持数组公式、条件格式、图表与跨表引用；
- 透视表按"当前工作表即数据表"建模，不支持多重值字段与计算字段；
- 宏为 JS 脚本（不是 VBA），无录制功能；
- `Altman Z`（市值口径）仍缺市值数据源，报告以 `Z''` 为准；
- 评测的"需要真实模型"套件默认不跑（要 `--with-llm` 与配额）；CI 默认只跑确定性套件。

> 数据来自公开信源，模型结果为规则化测算，不构成投资建议。
