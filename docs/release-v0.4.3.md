# v0.4.3 · 对话响应提速（思考流式展示 + 工具并行 + 卡死自愈）

> 发布日期：2026-09-09　｜　适用：Windows 10/11、macOS 11+（Apple Silicon / Intel）
>
> 修补版本，功能范围与 v0.4.2 一致；针对"模型调用太慢"的反馈做了可量化的优化。
> 已装 v0.4.0~v0.4.2 的同事建议升级。

## 先说结论：慢在哪里

用真实提问做耗时分解（"002842 和 002378 的毛利率为什么偏低"，4 轮工具调用）：

| 环节 | 优化前 | 优化后 |
|---|---|---|
| 工具调用 | 5.0 s（两次财务分析各 2.5 s） | **0.03 ~ 0.23 s** |
| 模型调用 | 20.1 s / 4 次 | 6.6 ~ 23 s（取决于回答长度） |
| 首字可见 | 0.5 s（但思考内容不显示，正文前"黑屏"） | **0.4 s 起流式显示思考过程** |
| 端到端（复杂问题） | 26.1 s | 23.8 s（模型侧主导，工具侧已不是瓶颈） |
| 单次问答（"康美风险怎么样"） | 10~15 s | **6.6 s** |

## 本次优化

### 1. 思考过程实时展示（感知速度大幅改善）

推理型模型会先输出 `reasoning_content`（实测一次提问 1,700~3,600 字），此前**完全没透传给界面**，
用户只能盯着空白等待。现在：

- 后端新增 `reasoning` 事件，逐字转发；
- 对话区出现可折叠的「🧠 正在思考…」块，实时增长，回答开始时自动收起；
- 顶部显示「⏱ 已用时 x.x s」，回答完成后给出耗时脚注：
  `⏱ 12.3s · 首字 0.5s · 86 tok/s · 末次输出 351 tok`；
- 每张工具卡片显示自身耗时（如 `get_financial_analysis 15ms`）。

### 2. 工具调用并行 + 去掉 2.5 秒空等

- **市值查询不再阻塞**：Altman Z 需要总市值，此前每次分析都同步等一次失败的网络请求（实测 2.5 s/次）。
  改为"全市场市值表后台拉取、命中即用"，拿不到就标注 Z 不可计算（Z'' 照常输出）；
- **同一轮的多个只读工具并行执行**：模型一次调用两家企业的财务分析时，由串行 2×2.5 s 变为并发；
- 写操作（刷新数据/添加企业/处置预警）仍保持串行 + 授权，不受影响。

### 3. 卡死自愈（顺带修掉 100 秒的"假死"）

实测出现过一次单次调用卡住、撞上 90 s 客户端超时后直接报错。现在：

- 单次调用超时 90 s → **60 s**；
- 网络/超时在**尚未输出任何内容**时自动重试 1 次（已输出则重试，避免重复 token）；
- 5xx/429 同样自动重试。

### 4. 回答更聚焦（直接减少最大头的输出耗时）

system 提示词要求：正文控制在 500 字内、只列 3~5 个关键数字、不用大表格罗列全部指标；
用户明确要"详细/完整报告"时才展开。

### 5. 新增「关闭模型思考」开关（可选提速）

设置 → 模型服务 → 「关闭模型思考」。实测同一问题的单次调用：

| 模式 | 耗时 | 输出 token | 正文长度 |
|---|---|---|---|
| 默认（带思考） | 4.16 s | 369 | 244 字 |
| 关闭思考 | **3.07 s（-26%）** | **174（-53%）** | 294 字 |

代价是复杂分析可能变浅，默认关闭；日常问答可自行开启。

## 使用提示

- 首次使用：右上角 ⚙ → 选提供商 → 填 API Key → 获取可用模型；
- 提问示例：`600518 现在风险怎么样？`、`002842 和 002378 的毛利率为什么偏低？`；
- 想更快：设置里开启「关闭模型思考」；想更细：让它"出完整报告"。

> 数据来自公开信源，模型结果为规则化测算，不构成投资建议。
