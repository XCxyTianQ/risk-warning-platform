# v1.0.0 回归结果：发布门禁未通过（并撤回一处因果归因）

> 回归：用 **v1.0.0 产品默认提示词**（不带任何预设）跑 FinanceBench oracle 150 题，
> 与"改动前产品默认"和"B6 预设"对照。仅用 deepseek-flash。
> 产物：`bench/external/out/chain-fb-2026-09-14T23-09-17.json`、日志 `out/chain-regression-v100.log`

## 一、结果：门禁未通过

| 配置 | 准确率 | 拒答 | 耗时/题 |
|---|---|---|---|
| 改动前产品默认（B0） | 86.58% | 4（2.68%） | 5,009 ms |
| B6 预设（规则"生效"时） | 86.24% | **0** | **~3,450 ms** |
| **v1.0.0 产品默认（本次回归）** | **85.33%** | **4（2.67%）** | **5,216 ms** |

**发布门禁的两条指标（拒答→0、耗时 −31%）一条都没达成**：
拒答仍为 4 题（2.67% vs 改动前 2.68%），耗时 5,216 ms（改动前 5,009 ms，无改善）。
准确率 85.33% 与改动前 86.58% 的差异在噪声内（n=150、judge@1 自判）。

## 二、排查：不是构建问题

对二进制做了字符串校验：

```
backend/target/release/risk-warning-backend.exe     含新规则标题: true  含规则片段: true
desktop/resources/backend/risk-warning-backend.exe  含新规则标题: true  含规则片段: true
```

**新规则确实编译进了 v1.0.0 运行时**，链路的 `--data-dir` 也是全新的（无 DB 覆盖）。
另确认系统提示只有 `backend/src/agent/prompt.rs` 一处来源（`server/app/agent/prompt.py` 是 Python 参考实现，不参与本次运行）。

## 三、根因：我的因果归因错了——B6 是"打包处理"

B6 预设实际同时改了三件事：

| 组件 | 内容 |
|---|---|
| ① 提示词修复 | `[作答模式]` 通用知识题直接作答、不要调用工具、只输出选项字母 |
| ② **工具白名单** | `tools=['__none__']`（平台 `retain_whitelist` 把空数组视为"不过滤"，此处传的是匹配不到任何工具的值） |
| ③ 技能 | 「客观题作答」严格输出契约 |

而 v1.0.0 只把 **③ 之外的一段"条件化 A1"**（证据充分性规则）搬进了基础提示。

**结论：拒绝回答的减少与延迟的下降，不是由"条件化 A1"这一段文字带来的**，
而是来自①②③的组合（最可能是②去工具——它改变了模型的整体任务框架）。
我此前把 B6 的整体效果归到了单个组件上，属**归因错误**，据此发布的 v1.0.0 变更说明需要更正。
