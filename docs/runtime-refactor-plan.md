# Agent 运行时重构方案（借鉴 DSH 架构，以「好用」为第一要务）

> 决策：采用**路线 B——重写自研运行时**，分层结构借鉴 DSH（开源）。
> 第一要务是**好用**：跑得完、不漂移、不卡死、看得见、能中断、权限可控。任何不改善这六项的"架构美感"都不做。

## 一、为什么是运行时，不是域层

本轮全部缺陷都落在运行时，域层表现良好：

| 缺陷 | 层 | 证据 |
|---|---|---|
| `is_async_tool` 手抄名单漏登记 → `unknown tool` | 运行时 | 模型看得见工具、调不动 |
| 工具声明/分发/异步名单/白名单**四处各写一遍** | 运行时 | 新增一个工具要改 4 处 |
| `MAX_STEPS` 硬编码 5 | 运行时 | 真实多步任务结构性跑不完 |
| 压缩把用户任务折成 ≤400 字自由纪要 → **任务漂移** | 运行时 | v8：85 次调用后跑去分析银行板块 |
| 授权是单一布尔 | 运行时 | 无 UI 环境永久阻塞 |
| 每个设置要在 `config.rs` + `settings.rs` 三处同步 | 运行时 | 加一个设置改 4 处 |
| HTTP 只有 `.query()`、无主机回退 | 基础设施 | `push2` 不可达即全线失败 |

域层（六维评分、Z''/Beneish M/Piotroski F、风险事实、预警）**是本平台真正的资产**，重构中保持不动，只是换成以声明方式暴露。

## 二、目标架构（六块，逐块对应一个已发生的缺陷）

### 1. 会话日志：事件溯源 + surface 投影
- `SessionEvent { seq, type, time, data }` 追加式日志（`turn/start`、`message`、`tool_call`、`tool_result`、`compaction/*`、`approval/*`）
- 发给模型的上下文由日志**投影**得出；**压缩 = 在投影里遮蔽一段 seq 范围，日志一字不动**
- 解决：压缩丢任务、无法回放/审计、中断不可恢复

### 2. 压缩：能力接缝 + 两级手段
- `Compactor` trait：`compact_if_needed(trigger)` / `compact_now()` / `compact_region(start,end)`
- **两级**：① **无模型剪枝器**（工具结果瘦身，记 `compaction/prune`）② LLM 结构化 checkpoint
- checkpoint 要求（照搬 DSH 的关键约束）：
  - **固定段落结构**，空段落写"（无）"但**不许省略**；含「用户原始请求（**逐字引用**）」「当前进度」「待办」「下一步」「关键约束」
  - **首条用户消息永不折叠**（放在 fold 范围之外）
  - 摘要必须**小于**被遮蔽内容，否则拒绝
  - 旧 checkpoint **合并**而非搬运
  - 压缩请求**复用同一 system prompt + 工具定义前缀**（不失效 KV 缓存）
- 解决：任务漂移（本轮最严重缺陷）

### 3. 工具：声明式注册，单一真源
```rust
struct ToolSpec {
    name, description, schema,
    read_only: bool,
    kind: Sync | Async,              // 由声明派生，不再手抄名单
    approval: Never | OnWrite | Always,
    mcp: Option<McpBinding>,
}
```
- 从声明**派生**：模型可见列表、同步/异步路由、预设白名单、审批策略、MCP 暴露
- **验收：新增一个工具只改一处**
- 解决：`unknown tool`、四处手抄

### 4. 权限：逐调用求值的策略层
- `PermissionMode { ReadOnly, Restricted, Full }` × `ApprovalClass` → `decide() -> Allow | Ask | Deny`
- **纯函数、可单测**（所有组合列成表测）
- 接设置项 + **桌面 UI 三档开关**；审批支持超时与"无人值守"策略
- 解决：无 UI 阻塞、权限不可控

### 5. 任务状态：任务锚 + 待办
- 显式 `TaskState { goal(逐字), todos[], progress }`，**每轮尾部注入**
- `MAX_STEPS` 由常量改为**可配置预算**
- 压缩后**自校验**：复述一次任务再继续
- 解决：漂移、跑一半停、目标丢失

### 6. 可观测
- 事件流落盘 + 前端可见：工具调用、压缩发生、审批等待、token/费用
- **"好用"依赖可见性**——用户要能看见"它在干什么、卡在哪"

## 三、分期（每期独立可交付，均以「好用」为验收门槛）

| 期 | 内容 | 验收 |
|---|---|---|
| **P0** | 引入 `SessionEvent` 日志 + surface 投影（双写，行为不变） | 26 套/115 断言回归全绿 |
| **P1** | 25 个工具迁到声明表；删除 `is_async_tool` 与各处白名单 | 新增工具只改一处（加测试） |
| **P2** | 压缩重构（剪枝器 + 结构化 checkpoint + 首条 pin + 收敛校验） | **任务 #1 在 85+ 次调用后不漂移** |
| **P3** | 权限策略层 + UI 三档开关 + 审批超时 | 无人值守跑通；UI 可切换 |
| **P4** | `TaskState` + 每轮任务锚 + 压缩后自校验 + 预算配置化 | 十家企业跑满且结论正确 |
| **P5** | 可观测面板（进度/工具/压缩/审批可见，可中断恢复） | 桌面端可见且可中断 |

## 四、「好用」的验收标准（可量化，避免自嗨）

1. **跑得完**：任务 #1（贵金属前十 + 逐家评估 + 全板块看法）在 YOLO 模式下一次跑完，**结论正确**（名单不多不少、无漂移）；
2. **不卡死**：全程无人值守，不弹授权、不无限等待；
3. **不漂移**：85+ 次工具调用后仍锁定原任务（P2 的核心验收）；
4. **看得见**：桌面 UI 显示进度、工具调用、压缩提示，**可中断、可恢复**；
5. **可回退**：`runtime_v2` 开关可切回旧路径；
6. **接入成本**：新增一个工具只改一处。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 重构期间产品不可用 | 旧路径保留 + feature flag，双写事件日志，可随时切回 |
| 一次性改动过大 | 分 6 期，每期独立可交付、独立验收 |
| 抄架构抄成"过度设计" | 每块都必须对应一个已发生的真实缺陷；不对应就不做 |
| 域层被牵连 | 域层（评分/财务/数据源/预警）**不在本期改动范围**，仅换暴露方式 |
| 上下文预算 | 分期交付，每期结束跑回归 + 任务 #1 验收 |
