# 企业数据接口接入方案（阶段3 前置调研）

> 结论先行：**可行，但要分两条路**——上市公司走免费自动化链路（已验证），非上市企业走"付费 API + 人工兜底"。
> 本文档基于 2026-09 实测（AkShare 1.18.94）+ 公开资料调研，作为阶段3 的实施依据。

---

## 1. 实测结果：免费链路能拿到什么

用 AkShare（开源免费，`pip install akshare`）实测某上市公司（600519）：

| 接口 | 能力 | 实测 | 对我们意味着 |
|---|---|---|---|
| `stock_financial_abstract` | 财务摘要 | ✅ (80 指标 × 105 报告期) | **财务维度**可直接自动化 |
| `stock_financial_report_sina` | 三大报表（利润表等） | ✅ (103 × 83) | 资产负债表/现金流可补齐 |
| `stock_news_em` | 个股新闻（东财） | ✅ 标题+正文+时间+来源+链接 | **舆情维度**直接自动化 |
| `stock_zh_a_disclosure_report_cninfo` | 巨潮公告 | ✅ 155 条（标题/时间/链接） | 公告/风险提示可自动化 |
| `stock_individual_info_em` | 基本信息 | ❌ 连接被重置 | 第三方接口偶发不稳，需重试/降级 |

**结论**：上市公司（A股）的**财务 + 公告 + 舆情**三条线，用免费开源库即可全自动获取，零成本。

## 2. 数据源对比矩阵

| 风险维度 | 推荐来源 | 成本 | 稳定性 | 合规要点 |
|---|---|---|---|---|
| 财务（上市公司） | **AkShare**（东财/新浪/巨潮） | 免费 | 中（偶发断连，需重试） | 公开披露数据，合规 |
| 公告/披露 | AkShare → 巨潮资讯 | 免费 | 中高 | 公开披露，合规 |
| 舆情新闻 | AkShare 个股新闻 / 通用新闻 API（聚合数据、天行数据等） | 免费额度 + 少量付费 | 中 | 只用公开新闻，注意版权与转载规范 |
| 工商信息（注册资本/股东/变更） | 企查查 / 天眼查 / 启信宝 **开放平台**；爱企查（网页） | 按量付费（有免费试用额度） | 高（商业服务） | 购买授权，遵守服务条款 |
| 司法（涉诉/执行/失信） | 企查查 / 天眼查开放平台 | 按量付费 | 高 | 同上；裁判文书网无官方 API |
| 知识产权（商标/专利） | 国家知识产权局公开数据（申请/开放目录）；商业库（智慧芽等） | 免费申请 + 商业付费 | 中 | 官方渠道优先 |
| 非上市中小企业 | **人工采集**（成员3 按模板）+ 公示系统人工查询 | 人力 | — | 只采公开信息，脱敏处理 |

> 参考：[企业数据 API 选型横评（天眼查/企查查/启信宝/鲸海）](https://www.cnblogs.com/xiaoxiang113/articles/20993631)、[国家知识产权局关于数据目录与 API 访问的答复](http://www.cnipa.gov.cn/jact/front/mailpubdetail.do?transactId=533908&sysid=12)、[2026 新闻 API 对比（免费额度/价格）](https://thunderbit.com/blog/best-news-apis-compared)。

## 3. 合规红线（务必遵守）

1. **只采公开数据**：上市公司披露、政府公开信息、公开新闻报道；
2. **不绕过技术措施**：不破验证码、不伪造身份、不越权访问（避免《刑法》285/286 条风险）；
3. **遵守 robots 与平台条款**：网页采集前检查 robots.txt 与服务协议；商业数据走正规 API 授权；
4. **个人信息保护**：涉及法定代表人/股东等自然人信息时脱敏存储（《个人信息保护法》）；
5. **数据来源可追溯**：每条事实保存 `source` + `date`（我们 `risk_fact` 表已按此设计）；
6. **不转售数据**：采集结果仅用于本项目内部研判与演示。

## 4. 架构设计：数据源适配层

```
app/datasources/
├── base.py         # DataSource 抽象：fetch(enterprise) -> NormalizedRecords
├── akshare_src.py  # 上市公司：财务 / 公告 / 新闻（免费）
├── manual_src.py   # 人工采集 CSV/Excel 导入（非上市兜底）
├── paid_api_src.py # 企查查/天眼查开放平台（阶段3-B，可后接）
└── registry.py     # 按维度选择源 + 失败降级 + 缓存
```

设计要点（与 `llm/tools.py` 的注册表模式一致）：

| 要点 | 做法 |
|---|---|
| 统一规范化 | 各源输出统一的 `FinanceRecord / NewsItem / LegalRecord` 结构，落库前不区分来源 |
| 失败降级 | 主源失败 → 备用源 → 缓存快照 → 标注"数据缺失"（不阻塞研判） |
| 限流与缓存 | 每个源独立限流 + 结果缓存（同一企业 TTL 内不重复拉取），控制成本与封禁风险 |
| 可追溯 | 每条记录带 `source`、`fetched_at`、`raw_ref`（链接） |
| 开关 | 数据源按配置启用/禁用（`.env` 或 DB 表），便于演示时只开免费源 |

接入点：`llm/tools.py` 的 `get_finance_data / get_news / get_legal_records` 由"读样例库"改为"读适配层"，
研判链路与 Agent 循环**无需改动**。

## 5. 分阶段落地路线

| 步骤 | 内容 | 依赖 | 工作量 |
|---|---|---|---|
| **3-A（立刻可做）** | AkShare 适配器：财务/公告/新闻 → 落库；配置股票代码映射表 | 无（已实测通过） | 2~3 人天 |
| **3-B（可选）** | 新闻 API 补充通用舆情（非个股新闻）；商标公开数据接入 | 免费额度/申请 | 1~2 人天 |
| **3-C（视预算）** | 企查查/天眼查开放平台：工商 + 司法 + 失信 | 购买按量包/试用 | 2 人天 + 预算 |
| **3-D（兜底）** | 人工采集模板 → CSV 导入器（成员3 使用） | 模板（可先给） | 1 人天 |

**预算参考**：免费路线 0 元；若要司法/工商全自动，第三方平台通常按调用量计费（小额包几百元起，需询价），建议先申请试用额度验证价值再决定。

## 6. 关键决策：样例企业要不要换成上市公司？

当前样例企业【杭州深度求索人工智能基础技术研究有限公司】**未上市** → 无公开财报，免费链路基本用不上。

建议**双轨样例**：

| 样例 | 用途 | 数据来源 |
|---|---|---|
| 上市公司（如贵州茅台 600519，或带风险事件的 ST 类公司） | 验证**自动化链路**（财务+公告+舆情全自动） | AkShare（免费） |
| 深度求索（非上市） | 展示**稀疏数据/数据缺失容忍**与人工采集路径 | 公开报道 + 人工 |

> 答辩时的叙事更完整：**"自动链路覆盖上市公司，人工+付费源覆盖中小企业，系统对数据缺失有容忍与标注能力。"**

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 免费接口不稳定（实测 1/5 失败） | 重试 + 备用源 + 缓存；失败标"数据缺失"不阻塞 |
| 第三方接口条款变化/限流 | 抽象适配层，源可插拔；不把业务逻辑绑死在某个源 |
| 采购成本超预算 | 先免费链路出效果，再按需购买试用额度 |
| 合规争议 | 只采公开数据、留存来源、不转售、脱敏 |
